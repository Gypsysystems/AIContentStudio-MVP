Create a high-fidelity, desktop-first SaaS web application prototype for an AI-powered content creation platform.

This is NOT a marketing website. Build the actual logged-in product experience.

PRODUCT PURPOSE

The platform helps professional authors, technical writers, instructional designers, product teams, and subject-matter experts transform source material into structured professional content using AI while keeping humans fully in control.

Users will eventually be able to create:

- User Guides
- Admin Guides
- Quick Start Guides
- SOPs
- Knowledge Base content
- eLearning courses
- Training Guides
- Interactive Tutorials
- FAQs
- Video and media content

For this first prototype, make USER GUIDE creation fully represented. Show other content types as future-ready options, but do not build their complete workflows yet.

DESIGN DIRECTION

Create a highly distinctive, premium, modern SaaS interface.

Do not make it look like:
- Microsoft Word
- Notion
- ChatGPT
- Microsoft Copilot
- Canva
- a generic admin dashboard

Use proven interaction principles from modern professional tools, but establish an original visual identity.

The experience must feel:
- clean
- intelligent
- calm
- professional
- highly productive
- spacious but not wasteful
- suitable for enterprise customers
- scalable to many future content types

Use restrained visual effects, excellent typography, subtle depth, smooth transitions, refined micro-interactions, and strong information hierarchy.

Design primarily for desktop/laptop authoring.

IMPORTANT AI UX PRINCIPLE

Do NOT keep a large permanent AI chat panel on the screen.

AI should appear contextually when required.

Use:
- contextual AI popovers
- floating AI command menus
- inline actions when text is selected
- compact modal experiences for large AI tasks
- background generation status
- contextual review suggestions
- source-reference overlays

The document itself must remain the main focus.

KNOWLEDGE MAP

Include a workspace mode called "Knowledge Map".

Authors should be able to switch between approximately:

Author | Structure | Knowledge Map

The Knowledge Map visually shows relationships between:

- topics
- concepts
- procedures
- features
- roles
- source documents
- related topics

Use synthetic nodes and relationships.

AI can suggest relationships, but users approve or reject them.

Clicking a node should open a lightweight contextual card showing:

- topic/concept name
- type
- connected topics
- source references
- where the content is used
- Open Topic action

Provide graph actions such as:

- Find Relationships
- Suggest Missing Topics
- Find Duplicates
- Check Source Coverage

Do not make this look like a technical database administration interface. Make it intuitive for content authors.

SOURCE TRACEABILITY

- transcript timestamp when relevant
